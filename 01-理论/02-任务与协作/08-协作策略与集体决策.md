# 08 · 协作策略与集体决策

> 前置：05—07。目标：针对不同不确定性选择协作方式，并保留裁决依据。

## 1. 不同策略解决不同问题

| 策略 | 希望获得的收益 | 主要风险 |
| --- | --- | --- |
| 分工执行 | 扩大覆盖、缩短独立工作的耗时 | 边界和集成失败 |
| 独立求解 | 保留不同假设与路径 | 重复成本、相关错误 |
| 交叉审核 | 发现作者忽略的问题 | 审核被作者结论锚定 |
| 辩论 | 暴露假设与争议 | 语言说服替代事实 |
| 投票 | 聚合可比较的独立判断 | 多数共享同一错误 |
| 专家路由 | 使用适合任务的能力 | 路由错误、专家成为瓶颈 |

若不清楚想降低哪种不确定性，就难以判断增加 Agent 是否有意义。

## 2. 独立性不是人数

两个客户端可能连接同一模型，两个模型可能使用同一错误资料，两个审核者也可能被同一方案提示引导。独立性应分别检查模型、信息源、推导路径、工具和组织职责。

本项目要求作者与验证者不同 kind，是降低共同盲点的一种代理措施。它不能保证模型不同，更不能证明错误独立。对事实问题，最终应返回原始证据；对代码行为，应执行测试或检查实际产物。

## 3. 分歧裁决的方法

先把分歧写成可以检查的命题：双方结论、输入版本、隐含假设和证据分别是什么。事实分歧通过更可靠资料或实验解决；目标偏好由需求负责人决定；工程取舍依据成本、风险和约束裁决。

裁决者需要合适能力和授权，不应仅因使用更强模型而自动拥有业务决策权。高代价、不可逆且证据不足的情况，应请求人工决策或缩小试验范围。

## 4. 防止无效辩论

提前规定争议问题、轮数或预算、证据要求、裁决者和退出条件。第一轮独立形成判断，之后再交流差异，有助于减少过早趋同。已经被实验否定的假设不因重复表达而重新获得权重。

例如两个 Worker 分别支持两种会话方案。先比较安全约束、现有兼容性和迁移成本，再进行小范围验证。若主要分歧是产品是否允许强制重新登录，需要需求决策，增加辩论轮数不能解决。

## 5. 研究与工程任务的区别

研究任务可能适合按独立资料方向并行；工程任务常有共享接口、环境和写入冲突。不能直接把研究系统的收益迁移到代码开发任务。Anthropic 案例可用于理解委派与并行研究，但需要在本业务上复验收益。[工程案例](https://www.anthropic.com/engineering/multi-agent-research-system)

CrewAI 提供顺序和层级流程，可以作为组织实现参照；流程存在并不自动证明质量提升。[Processes](https://docs.crewai.com/en/concepts/processes)

## 6. 练习与验收

为“查资料”“实现接口”“选择迁移方案”各设计协作策略，写明独立性来自哪里、如何合并结果、何时停止，以及什么证据会推翻多数意见。
