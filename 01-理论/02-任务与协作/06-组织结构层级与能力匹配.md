# 06 · 组织结构、层级与能力匹配

> 前置：03—05。目标：根据任务决定组织，而不是让任务服从固定层级。

## 1. 四个独立变量

层级深度影响决策传播距离；管理跨度影响协调者负载；并发宽度影响资源占用；授权范围影响局部自主程度。增加层级不必然增加并发，减少层级也不必然减少协调。

选择结构时，可以先估计下级数量、汇报频率、异常比例和每次裁决成本。协调者持续处理重复事务时，可以增加组长或自动化规则；任务少且依赖简单时，增加中间层通常只增加交接。

## 2. 五角色的职责与可选层级

secretary 负责需求入口与对用户汇报，保留响应能力；planner 维护全局计划、依赖和收口；group 管理单域的一组任务；worker 交付边界明确的产物；verifier 独立检查。

本项目采用单一用户出口，便于统一口径；其他系统可以有多个受控入口，但必须解决版本、冲突和责任归属。规划、分派、收口、裁决也并非理论上必须由同一实例承担；集中有利于一致性，拆分则需要明确交接和权威状态。

在本项目运行任务时遵守现有角色约束；一般设计讨论中，可以按规模合并职责。独立验证不能只靠同一执行者换个角色名称实现。

## 3. 分级依据与升降级

| 组织选择 | 主要判断 | 调整信号 |
| --- | --- | --- |
| 单 Worker | 输入清楚、责任集中、可独立验收 | 发现必须跨域决策则升级 |
| 单组 | 同域多任务、局部负责人能划清边界 | 需要跨组接口或全局取舍则升级 |
| 全局策划 | 多域依赖，需要统一方案和收口 | 只剩一个独立任务时缩减结构 |
| 更强决策能力 | 方案不明确、冲突难裁决、错误代价高 | 方案稳定后把执行交回常规资源 |

T0、组级、T1、T2 是本项目的实践标签。文件数和预计时间可作为初筛，不应机械替代风险、依赖和可验证性判断。升降级应保留计划、产物、证据和未解决问题。

## 4. 能力匹配的顺序

先检查硬条件：权限、工具、模态、环境和上下文是否满足；再比较代表任务上的质量；最后在满足目标的候选中优化成本、时延和负载。稀缺模型适合高价值判断，但不能假定昂贵模型永远适合所有裁决。

派活矩阵应写出任务类型、能力要求、首选、备选、依据和复验日期。新增 Worker 先通过代表任务，再进入矩阵，不以“已经安装”作为可派活依据。

## 5. 拓扑与布局

| 协作形态 | 使用条件 | 关键机制 |
| --- | --- | --- |
| 单 Agent 加子任务 | 主体需要保持完整目标，局部工作可委派 | 明确返回值与上下文边界 |
| 并行任务池 | 独立、同类任务较多 | 领取、依赖检查、去重与公平性 |
| 星型或层级 | 需要统一决策或分域管理 | 管理跨度、授权与汇总 |
| 流水线 | 阶段契约较稳定 | 输入输出版本、背压与阶段重试 |
| 共享黑板 | 多方依据共享事实持续贡献 | 权威数据、并发更新与触发规则 |
| 网状协作 | 专业间需要密集交换 | 通信范围、议题控制与裁决 |

黑板是共享问题状态与产物的协作方式，不只是群聊记录；任何执行者都不能无条件覆盖其他人的事实。

星型便于统一决策，流水线适合稳定阶段，网状适合密集专业交流但通信成本高。终端按任务分页便于追踪交付，按部门分页便于管理同类资源；根据主要观察对象选择，并保留任务 ID。

可视窗格有助于人工发现卡住和配置错误，但不是分布式系统必须采用的部署形式。最小可读尺寸应通过关键状态能否看清判断，不应只看几何大小。

可以在计划中的最大并发下检查：实例身份、实际模型、任务状态、最近错误和输入提示是否仍可辨认；若窄窗格截断关键字段，应减少同页数量或改用结构化状态表。部门分页适合同类资源观察，任务分页适合跟踪一次交付；命名和任务 ID 保证两种视图可以互相定位。

## 6. 练习与验收

为独立文档修改、单域批量处理、跨模块认证改造各选一种结构；解释层级、跨度、并发与授权。若所有任务都选同一阵容，重新检查是否真正依据任务做了判断。
