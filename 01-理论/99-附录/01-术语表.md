# 术语表

本文是仓库内部统一用语，不要求外部项目使用相同定义。

| 术语 | 英文 | 本文含义 |
| --- | --- | --- |
| 目标 | Goal | 希望达到的业务结果 |
| 任务契约 | Task contract | 输入、目标、范围、验收和执行约束 |
| 任务 | Task | 可跟踪、可验收的工作单元 |
| 执行尝试 | Attempt | 同一任务的一次具体执行，重派后改变身份 |
| 角色 | Role | 责任分工，不等于独立进程 |
| 执行逻辑 | Agent | 根据目标与反馈选择行动的逻辑 |
| 广义执行单元 | Worker | 承载 Agent 或确定性程序的运行单元 |
| 末端执行角色 | worker | 现有实操协议中负责边界清晰任务的角色 |
| 秘书 | secretary | 本项目需求入口和用户汇报出口 |
| 策划 | planner | 全局方案、依赖、分派和收口负责人 |
| 组长 | group | 单域一组任务的管理角色 |
| 验证者 | verifier | 根据标准独立检查产物的角色 |
| 客户端类型 | kind | 本项目的客户端类别，不等于实际模型 |
| 档位 | Tier | 本项目组织或能力分派标签，需按上下文区分 |
| 技能 | Skill | 可复用方法、流程、约束和资源 |
| 模型上下文协议 | MCP | 连接工具和资源等能力的协议 |
| 编排 | Orchestration | 管理依赖、状态与执行协调 |
| 调度 | Scheduling | 决定何时把任务分配给哪个资源 |
| 运行时 | Runtime | 启动、管理执行与消息处理的环境 |
| 期望状态 | Desired state | 控制系统希望持续满足的状态 |
| 控制循环 | Reconciliation loop | 观察实际状态并纠正偏差 |
| 检查点 | Checkpoint | 为继续执行保存的状态快照，范围须明确 |
| 交接包 | Handoff package | 目标、状态、产物、证据和后续步骤的集合 |
| 租约 | Lease | 在有效期内授予某种资格的机制 |
| 隔离代次 | Fencing token | 接收方用于拒绝旧执行者操作的单调身份标记 |
| 幂等 | Idempotency | 同一业务操作重复请求不会重复产生约定效果 |
| 去重 | Deduplication | 识别并过滤重复消息或请求 |
| 补偿 | Compensation | 对已发生效果执行后续修正，未必完全可逆 |
| 背压 | Backpressure | 将下游容量限制传回上游 |
| 关键路径 | Critical path | 决定总完工时间的最长依赖链 |
| 自证材料 | Evidence package | 作者提供的可复现证据，不代替独立验收 |
| 收口 | Integration and closure | 合并、验收并总结任务结果，不等于关闭实例 |
| 基线 | Baseline | 用于比较改进收益的固定参照方案 |
| 消融实验 | Ablation | 移除或改变某机制以观察其作用 |
