# 18 · 理论基础与研究方向

> 前置：先完成一个小型协作系统，再围绕实际问题深入。目标：用理论解释取舍，识别模型假设。

## 1. 图论与并行计算

任务图帮助描述依赖和关键路径。若可并行部分比例为 p，处理资源数为 n，忽略协调和资源争用时，理想加速比可近似写为 1／((1−p)+p／n)。这是简化的并行上界模型，不是 Agent 效果预测公式。

真实系统还需加入启动、交接、冲突、验证和返工。学习目标是识别串行部分和瓶颈，而不是用更多 Worker 掩盖任务依赖。

## 2. 分布式系统与状态机

消息可能延迟、重复和丢失；不同节点看到的状态可能不一致。故障检测无法仅凭超时立即知道远端事实，因此需要任务所有权、租约、版本校验和幂等。

进一步学习事务、事件日志、乐观并发、消息确认、领导者选举和补偿。重点理解每种机制保证到哪里，例如状态表原子更新不自动覆盖外部 API 副作用。

## 3. 排队论与容量规划

在满足稳定性和统计口径等条件时，平均在系统中的任务量 L、到达率 λ 和平均停留时间 W 满足 L＝λW。这里的停留时间包括等待与处理。

接近服务容量时，等待可能显著增加。观察到队列很长，先判断是资源不足、上游突发还是下游阻塞。对模型调用配额、共享测试环境和工具连接分别建模，不应只统计 Worker 数量。

## 4. 控制理论与自动纠偏

控制器读取误差并采取动作。反馈存在延迟，动作过强可能振荡。例如排队增加就立即扩很多实例，几秒后又因队列下降全部回收，会反复支付启动成本。

学习采样周期、反馈延迟、稳定区间、迟滞与控制器所有权。将“扩容到多少”视为反馈设计问题，而不仅是阈值配置。

## 5. 优化、组织与决策理论

资源分配可以建模为在质量、时间、成本和权限约束下选择执行者与顺序。多目标通常不能同时最优，需要明确优先级或允许的质量下限。

组织理论帮助理解管理跨度、授权和协调成本；决策理论帮助判断是否值得继续搜索或验证。一个简化思路是比较额外信息可能减少的决策损失与获取成本，但概率和损失估计应有依据。

## 6. 进阶问题与研究规范

可以继续研究部分可观测决策、异构模型协作、动态组织、在线路由和多 Agent 学习。区分“用多个模型协作完成任务”与“训练多个学习主体”，后者的理论和实验条件不完全相同。

研究问题应写明任务分布、基线、资源约束、评价方法和可复现材料。框架支持某功能，只能证明实现方式存在，不能证明其在当前业务上有效。

## 7. 练习与验收

从真实失败中选择一个问题，分别用依赖图、队列和状态机解释，指出各自能解释和不能解释的部分。为计划采用的机制写出假设与反例，再设计最小验证。
